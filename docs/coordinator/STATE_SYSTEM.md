# ACE state system — one entrypoint, zero manual ops

## Owner experience (you do nothing)

1. Open OpenCode at the Desktop repo root. The `ace-state` plugin
   auto-injects live state on `session.created` — branch, commit, task
   statuses, contracts. No `--write`, no `--brief`, no research.
2. Type `/status` — 15-line Vietnamese summary: which tasks are ready,
   running, done, blocked, next dispatch.
3. Type `/dispatch W1-rights-scope` — worker starts with packet plus
   fresh state, writes report, auto-refreshes state on every file edit
   via `tool.execute.after`, stops. Compaction re-anchors to STATE.json
   so long sessions never lose truth.
4. You inspect the report plus render, say OK, move to next `/dispatch`.

## Single entrypoint

- Humans and coordinator open `docs/coordinator/PROGRESS.md`. It is
  auto-generated by `python tools/ace_state.py --write` and contains live
  facts plus the full `docs/ENGINE_STATE.md` handoff prose quoted at the
  bottom. No separate checkpoint to keep in sync.
- Workers read `docs/coordinator/STATE.json` (same run, machine-readable).
- `docs/ENGINE_STATE.md` remains the only hand-edited state prose, owned
  by the coordinator. It is never duplicated — PROGRESS.md quotes it.

## Layers

1. `docs/coordinator/STATE.json` — machine truth, auto-generated by
   `python tools/ace_state.py --write`. Holds branch, commit, dirty files,
   worktrees, goal, contracts with sha, task statuses, test list, recent
   renders, must-read list. Workers read this (~175 lines JSON) instead of
   grepping the repo. Refresh after every report; `--check` says
   FRESH or STALE.
2. `docs/coordinator/PROGRESS.md` — human dashboard, auto-generated from
   the same run. Tasks, contracts, renders, dirty files at a glance.
3. `docs/ENGINE_STATE.md` — owner handoff prose, coordinator-owned,
   updated at workstream end with verified outcomes only.

## Why this beats a single checkpoint md

- Old habit: model reads ENGINE_STATE.md plus 3+ docs, re-derives git,
  contracts, task status every dispatch (~10-15 calls, drift risk).
- Now: one `STATE.json` read gives branch/commit, contract shas, task
  statuses, renders. PROGRESS.md gives humans the same plus quoted
  handoff. Gossip between two checkpoints is impossible because only
  ENGINE_STATE.md is hand-edited.

## Commands

- `python tools/ace_state.py --write` — refresh after each report
- `python tools/ace_state.py --check` — FRESH or STALE before dispatch
- `python tools/ace_state.py --brief W1-rights-scope` — dispatch card
- `python tools/ace_state.py --json` — raw state for scripting

## Sync protocol — never drift again
1. **Only one working root:** Desktop repo (`C:\Users\Infomation Technolog\Desktop\autonomous-content-engine-v1`). Never open or edit in `Documents\Default Project\...` copies — they caused the 4-week drift.
2. **Before every session:** run `python tools/ace_state.py --check`. If `STALE`, sync before dispatching.
3. **Sync (no commit, no push):** `git fetch origin main` then `git checkout origin/main -- .`. This brings origin/main's released code into the working tree without touching your untracked coordinator files (`.opencode/`, `AGENTS.md`, `docs/coordinator/`, `tools/`, `opencode.json`, `docs/ENGINE_STATE.md`). Then run `python tools/ace_state.py --write`.
4. **Offline fallback:** `git remote add local_default <path-to-Default-Project-copy>` then `git checkout local_default/main -- .` + `python tools/ace_state.py --write`.
5. **After each workstream:** `python tools/ace_state.py --write` so STATE.json and PROGRESS.md stay live.
6. **You commit when ready:** staged changes wait for your explicit `git commit`. No auto-commit ever.
